Invariants for the native layer: the Tauri capability allowlist that keeps notes on disk, the `noten-asset` scheme, and the headless-Edge PDF export command.

## Capability Surface

Noten's privacy posture is "your notes never leave the disk," and it should stay verifiable through the Tauri capability allowlist in `src-tauri/capabilities/default.json`:

- File access uses the broad `fs:read-all` / `fs:write-all` commands but is constrained by `fs:scope` to `$APPDATA`, `$APPLOCALDATA`, and `$HOME`. Do not widen this scope without a concrete need.
- The `noten-asset` scheme serves only image files (by extension) whose canonical path lies inside a `.assets` directory under `$HOME`, `$APPDATA` or `$APPLOCALDATA`; the rule is fixed in `is_servable_note_image`, so dialog-picked paths cannot widen it the way they widen Tauri's asset-protocol scope. `resolveRenderableImageSource` additionally refuses any image source that is not a managed `.assets/` path or inline data. PDF export goes through the same rule (`note_image_files`) before it hands Edge a `file:` path. Keep these restrictions. Tauri treats a registered scheme's origin as local (it would get the app's IPC permissions if the window navigated there), so every `noten-asset` response carries `Content-Security-Policy: … sandbox` and `nosniff`; keep them.
- There is no HTTP-client plugin. The only outbound network is `tauri-plugin-updater` (checks GitHub releases) and `opener` (hands links to the system browser; it does not transmit note content). Do not add `http:` or other network permissions just to make a feature easier — a local-first note app should not phone home.

## PDF Export (print_to_pdf)

- `print_to_pdf` treats the PDF as done only once the file it asked Edge to write exists and no process holds it open. The launched `msedge.exe` can exit with success before the PDF is written (it handed the job to another Edge process while an Edge update was pending); deleting the temp HTML then printed Edge's "file not found" page. Edge prints to a temp path, which is copied (not renamed, so it inherits the target folder's permissions) to the chosen file.
- `print_to_pdf` temp files are per-invocation (pid + timestamp + counter): a fixed name let two windows exporting at once overwrite each other's HTML and render the wrong note. They hold the full note body in plain text, so every return path must delete them.
- Edge is spawned, not `output()`-ed: the run is bounded by `PDF_RENDER_TIMEOUT` and the child is killed on expiry, so a wedged headless Edge cannot leave the `invoke` pending forever. A renderer that runs out of memory (a note with ~500 MB of images needed ~10 GB) makes Edge exit without a PDF, or with the default profile hang until the timeout; `failure_reason` names it from Edge's log, and an exit after such a crash fails at once instead of waiting for a PDF. Edge can also finish writing the PDF and then not exit, so the wait loop accepts a written, closed PDF while Edge still runs. Edge runs with its own `--user-data-dir` per export, removed afterwards (without it every export left a `%TEMP%\HeadlessEdge<N>` folder behind, 3 GB after a day of testing), and with extensions, sync, component updates and background networking off, so printing makes no network requests of its own. Its stderr goes to a file rather than a pipe — nothing drains a pipe while we poll for exit, so a chatty child could block and then be killed spuriously.
